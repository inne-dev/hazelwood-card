## Minecraft and Paper

- Minecraft Java 26.3 is a full release, published September 15, 2026 ([Mojang release notes](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-3)).
- Paper's requirements table says Minecraft 26.1+ uses Java 25 ([Paper setup guide](https://docs.papermc.io/paper/getting-started/)). The local server compose file currently sets `TYPE=PAPER`, `VERSION=26.1.2`, and image `itzg/minecraft-server:java25` ([local `docker-compose.yml`](/Users/andy/Projects/minecraft-server/docker-compose.yml)). Thus its runtime Java already meets 26.3's documented requirement; the server version still needs updating.
- The official PaperMC downloads API currently lists build `166` as the newest 26.3 build, in the `BETA` channel, with no stable 26.3 build listed. The itzg Minecraft image uses `PAPER_CHANNEL=experimental` to permit these pre-release builds ([Paper downloads API](https://fill.papermc.io/v3/projects/paper/versions/26.3/builds), [itzg Paper docs](https://github.com/itzg/docker-minecraft-server/blob/master/docs/types-and-platforms/server-types/paper.md)). The requested minimum version therefore requires accepting a beta build today.
- Paper's 26.3 update notice says to back up first and that a world upgraded to 26.3 cannot be downgraded to an earlier version ([Paper 26.3 notice](https://papermc.io/news/26-3/)). Preserve a full world backup before the first 26.3 boot.

## BlueMap and map caching

- BlueMap 5.28 is the latest official release checked on 2026-10-09; its Paper plugin asset is `bluemap-5.28-paper.jar` (SHA-256 `4cfb4a9963132d5be0a9db031a28a98e9df92deed37ebb0756d3a7dd8721ab98`, from the official GitHub Release API). BlueMap 5.24's release already documented Paper/Folia 26.1.1–26.3 and Java 25 support ([BlueMap v5.24](https://github.com/BlueMap-Minecraft/BlueMap/releases/tag/v5.24)); the 5.28 asset is pinned for installation. Its official installation guide says Paper plugins render/update maps as the world changes and includes a built-in webserver ([installation](https://bluemap.bluecolored.de/wiki/getting-started/Installation.html)).
- Exact v5.24 Paper asset URL: <https://github.com/BlueMap-Minecraft/BlueMap/releases/download/v5.24/bluemap-5.24-paper.jar>. The official release page does not show a checksum in the rendered asset listing. A third-party SourceForge mirror lists SHA-256 `23592af35d1289ff9251301994948f1d69e8d81b569515ce81a91cba4daabc78`; treat this as mirror-provided, not an official BlueMap checksum ([mirror file page](https://sourceforge.net/projects/bluemap.mirror/files/v5.24/bluemap-5.24-paper.jar/download)). The official release listing now shows v5.28 as newer, with the same Paper/Folia 26.1.1–26.3 target; prefer the latest release unless intentionally pinning v5.24 ([BlueMap releases](https://github.com/BlueMap-Minecraft/BlueMap/releases)).
- Prefer the latest v5.28 Paper asset: <https://github.com/BlueMap-Minecraft/BlueMap/releases/download/v5.28/bluemap-5.28-paper.jar>. GitHub's Releases API exposes an asset `digest` field ([GitHub API docs](https://docs.github.com/en/rest/releases/assets?apiVersion=2022-11-28)); the v5.28 Paper asset's official digest is `sha256:4cfb4a9963132d5be0a9db031a28a98e9df92deed37ebb0756d3a7dd8721ab98`. I downloaded this exact official URL into `/private/tmp` and verified it locally with `shasum -a 256`; the result matched the API digest.
- BlueMap stores generated tiles on disk by default (`file` storage); the default is GZIP compression, recommended by BlueMap. High-resolution tiles are compressed PRBM files; low-resolution overview tiles are PNG files. These files can be served as static assets and cached by the site web server/CDN ([storage docs](https://bluemap.bluecolored.de/wiki/customization/Storages.html), [external webserver docs](https://bluemap.bluecolored.de/wiki/webserver/ExternalWebserversFile.html)). Keep BlueMap's `/maps/*/live/*` endpoint proxied if using live player markers.
- BlueMap's perspective view is enabled by default. It incrementally updates changed chunks; its periodic full update checks for missed changes and does not re-render the entire map ([map config](https://bluemap.bluecolored.de/wiki/configs/Maps.html), [core config](https://bluemap.bluecolored.de/wiki/configs/Core.html)).
- The official reverse-proxy examples support serving BlueMap under `/map/` by stripping that prefix before forwarding to port 8100. No separate BlueMap base-path setting is required ([reverse-proxy docs](https://bluemap.bluecolored.de/wiki/webserver/ReverseProxy.html)).
- To reduce load and disk use, configure `render-thread-count: 1`, bound the render area with a render mask, and consider a positive `min-inhabited-time` so it only renders chunks players have visited. BlueMap documents the CPU tradeoff for render threads and that the mask/inhabited-time can bound output ([core config](https://bluemap.bluecolored.de/wiki/configs/Core.html), [map config](https://bluemap.bluecolored.de/wiki/configs/Maps.html)). Hires can be disabled to make rendering faster and map files much smaller, at the cost of detailed 3D tiles.
- BlueMap's own lightweight webserver is sufficient for low concurrency; its docs recommend a separate webserver such as NGINX or Apache if concurrent map viewers become a concern ([external webserver docs](https://bluemap.bluecolored.de/wiki/webserver/ExternalWebserversFile.html)).
- For mounting BlueMap at `/map/`, its official reverse-proxy guide gives NGINX `location /map/ { proxy_pass http://127.0.0.1:8100/; }` or Caddy `handle_path /map/* { reverse_proxy 127.0.0.1:8100 }`. The trailing slash / `handle_path` strips the prefix before forwarding; no BlueMap base-path setting is needed ([reverse-proxy guide](https://bluemap.bluecolored.de/wiki/webserver/ReverseProxy.html)).

## Minimum server integration

- **Only required third-party plugin: BlueMap 5.24.** A separate status plugin is not necessary for online count/name display: Paper's built-in server status listener supplies status, and `hide-online-players` controls whether its status response hides the player list ([Paper `server.properties` reference](https://docs.papermc.io/paper/reference/server-properties/)). Locally, `enable-status=true` and `hide-online-players=false`; `enable-query=false` is fine for status ping and should stay off unless GameSpy4 Query is specifically needed ([local `server.properties`](/Users/andy/Projects/minecraft-server/data/server.properties)). The site backend can poll the Minecraft status protocol and cache the result briefly.
- Admin bans can use Paper's built-in `/ban`, `/pardon`, and `/banlist players` commands; the server maintains `banned-players.json`. Paper explicitly advises using commands instead of editing that file directly ([vanilla data files](https://docs.papermc.io/paper/reference/vanilla-data-files/)). No general admin plugin is required. If the website executes bans through RCON, keep RCON reachable only on a private container/network boundary; Paper describes it as remote access to the server console ([server properties](https://docs.papermc.io/paper/reference/server-properties/)). A custom bridge plugin is optional, useful only if the site needs richer live stats or a narrow in-process API.
- **Identity caveat:** local `server.properties` has `online-mode=false` ([local file](/Users/andy/Projects/minecraft-server/data/server.properties)). Paper documents that `online-mode=true` verifies connections against Minecraft accounts ([server properties](https://docs.papermc.io/paper/reference/server-properties/)). If website accounts are meant to prove ownership of an in-game nickname, the site password alone cannot authenticate that player to Minecraft; keep an in-game auth mechanism or change to online mode and bind profiles to verified UUIDs.
